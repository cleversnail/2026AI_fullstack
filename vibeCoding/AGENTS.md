## 2. 设计对齐与视觉规范（Figma 优先）
- **设计来源**：本次登录注册模块以 Figma 设计稿为唯一视觉标准。
- **设计 Token 遵守**：所有颜色、边距、字号、圆角**必须**使用定义好的 CSS 变量或 Tailwind 配置文件中的 Token，**严禁硬编码**（例如禁止直接写 `bg-[#1890ff]` 或 `color: #333`，应使用 `--color-primary` 或对应 token）。
- **尺寸与响应式**：PC 端设计稿基于 1440px 宽度设计。登录框需支持居中自适应，在 1280px 到 1920px 屏幕下不能出现水平滚动条或严重变形。

## 3. 功能与状态要求（登录注册模块特有）
实现以下交互状态，缺一不可：
- **默认状态**：输入框空、按钮置灰或不可点击。
- **输入态**：focus 时的高亮边框、阴影。
- **校验态**：邮箱/手机号格式错误、密码长度不符时的实时或失焦错误提示（Error Message）。
- **加载态（Loading）**：点击登录/注册按钮后，按钮进入 loading 动画并禁用，防止重复提交。
- **切换态**：登录页与注册页、忘记密码页之间的平滑切换（路由跳转或组件切换）。

## 4. 编码红线（Don't）
- 不准使用非授权的第三方 UI 组件库（如已有 Antd/Element，则基于其定制，不要擅自引入第三套 UI 库）。
- 严禁出现未经处理的表单报错。
- 不要写内联样式（Inline Styles），一律使用样式类或 Token。

## 5. 完成标准（Definition of Done）
- 代码通过 `npm run lint` 和 `npm run typecheck`。
- 登录/注册的所有核心交互（输入、校验、提交、报错、成功跳转）逻辑闭环。
- 视觉效果与 Figma 设计稿实现 1:1 像素级/结构级对齐。
